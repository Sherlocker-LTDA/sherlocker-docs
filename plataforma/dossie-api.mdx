Envie `POST /dossies` com os módulos que deseja consultar. **Não é necessário enviar `mode`.**

```json
{
  "document": "52998224725",
  "modules": ["processos", "dividas"]
}
```

Este pedido consulta processos e dívidas do alvo, não uma investigação completa.
A resposta `202` confirma o aceite. Acompanhe `GET /dossies/{dossie_id}/status`
e obtenha o resultado e o PDF em `GET /dossies/{dossie_id}`.

## Escolha a entrada

| Caso | Envie | O que acontece |
| --- | --- | --- |
| Só consultas | `document` + `modules` | Consulta os módulos selecionados. |
| Só seus dados | `data` | Gera o relatório com o conteúdo enviado, sem consultas externas. |
| Consultas + seus dados | `document` + `modules` + `data` | Combina os resultados consultados e os dados enviados, identificando suas origens. |

`document` é um CPF/CNPJ válido em string. É obrigatório quando há módulos.
Em pedidos somente com `data`, pode ser informado para identificar o alvo, sem iniciar consultas.
Enviar apenas `document`, sem `modules` nem `data`, mantém a investigação padrão existente.

### 1. Só módulos

`modules` é uma lista. Use strings para selecionar módulos ou objetos para configurar processos e conexões:

```json
{
  "document": "52998224725",
  "modules": [
    "dividas",
    {"nome": "processos", "config": {"categorias": ["criminal", "civel"]}},
    {"nome": "conexoes", "config": {"graus": 1}}
  ]
}
```

Não repita um módulo, mesmo misturando string e objeto. `modules: []` é inválido.

| Seletores | Consulta |
| --- | --- |
| `cadastro` | Dados cadastrais do alvo. |
| `empresas`, `empregos`, `beneficios` | Empresas relacionadas, vínculos e benefícios de pessoa física. |
| `dividas`, `processos`, `protestos` | Dívidas, processos e protestos nas fontes disponíveis. |
| `veiculos`, `imoveis` | Registros patrimoniais disponíveis, sem garantia de cobertura integral. |
| `sancoes`, `restricoes` | Listas e restrições disponíveis, não uma certidão de regularidade fiscal. |
| `telefones`, `emails` | Contatos de pessoa física. |
| `funcionarios`, `compliance`, `historico` | Informações de pessoa jurídica. |
| `conexoes`, `redes` | Relações e candidatos a perfis sociais. Um candidato não confirma titularidade. |

`web` não está disponível: o servidor rejeita sua seleção por segurança.

Configurações aceitas:

- `processos`: `config.categorias` aceita `criminal`, `civel`, `trabalhista` e `tributario`; `config.numeros` aceita até 100 números CNJ em string, formatados ou com 20 dígitos. Os filtros se aplicam aos processos do alvo, não são uma busca livre por número.
- `conexoes`: a string `"conexoes"` usa grau `1`; `config.graus` aceita `1`, `2` ou `3`. Expandir conexões não autoriza consultar todos os outros módulos para cada pessoa relacionada.
- Demais módulos: selecione pelo nome, sem inventar opções de configuração.

A cobertura depende da fonte. Protestos não significa cobertura nacional. Consulte as limitações no resultado, inclusive truncamento ou indisponibilidade.

### 2. Só dados personalizados

`data` é uma lista de blocos com origem e campos tipados. Não é necessário selecionar um módulo para usar seus próprios dados. Sem `document`, cada bloco precisa identificar o mesmo alvo em `referencia.documento` ou `referencia.nome`. Com `document`, referências documentais devem corresponder ao alvo.

```json
{
  "data": [
    {
      "id": "avaliacao",
      "titulo": "Avaliação interna",
      "referencia": {"nome": "Fornecedor de exemplo"},
      "origem": {"nome": "Equipe de compras"},
      "campos": [
        {"chave": "observacao", "dado": {"tipo": "texto", "valor": "Documentação recebida para revisão."}},
        {"chave": "revisado", "dado": {"tipo": "booleano", "valor": false}}
      ]
    }
  ]
}
```

Nenhuma fonte externa é consultada nesse pedido. Os dados são apresentados como informações fornecidas pelo cliente, não como fatos verificados pelo Sherlocker.

### 3. Seus dados + módulos Sherlocker

Exemplo: o cliente envia dados do seu sistema interno e pede ao Sherlocker apenas os processos da pessoa analisada.

```json
{
  "document": "52998224725",
  "modules": ["processos"],
  "data": [
    {
      "id": "cadastro_interno",
      "titulo": "Dados fornecidos pelo cliente",
      "referencia": {"documento": "52998224725", "nome": "Pessoa de exemplo"},
      "origem": {"nome": "Sistema interno do cliente"},
      "campos": [
        {"chave": "codigo", "dado": {"tipo": "texto", "valor": "cliente-8472"}},
        {"chave": "observacao", "dado": {"tipo": "texto", "valor": "Cadastro recebido para revisão."}},
        {"chave": "proxima_revisao", "dado": {"tipo": "data", "valor": "2028-06-30"}},
        {"chave": "documentacao_recebida", "dado": {"tipo": "booleano", "valor": true}},
        {"chave": "situacao", "dado": {"tipo": "ausente", "motivo": "nao_informado"}}
      ]
    }
  ]
}
```

O Sherlocker consulta processos e inclui os dados do cliente no mesmo relatório. **Os dados enviados não são verificados em uma fonte externa.** A existência de processo não significa condenação.

## Tipos dos seus dados

Cada campo tem `chave`, `rotulo` opcional e `dado`. O assunto é livre, mas o valor deve respeitar um destes tipos:

| `tipo` | Conteúdo |
| --- | --- |
| `texto` | `valor` string, inclusive registros e identificadores. |
| `inteiro` | `valor` inteiro, sem converter texto em número. |
| `decimal` | `valor` numérico finito. |
| `booleano` | `valor` booleano: `true` ou `false`. |
| `data` | `valor` com data real no formato `YYYY-MM-DD`. |
| `instante` | `valor` com data/hora ISO 8601 e fuso. |
| `dinheiro` | `valor` com `quantia` decimal em string e `moeda`: `BRL`, `USD` ou `EUR`. |
| `ausente` | `motivo`: `nao_informado`, `desconhecido` ou `nao_aplicavel`, sem `valor`. |
| `objeto` | `campos`: lista de campos tipados. |
| `lista` | `itens`: lista de valores tipados. |

Origem declarada pelo cliente não é certificação. Texto ou URL em um campo não provoca download, OCR ou execução de instruções. Não envie credenciais como conteúdo do relatório.

## Módulos não são seções

**`modules` define o que consultar. Seções definem como apresentar o que já existe.**
Selecionar processos não obriga a ter apenas uma seção, e pedir uma seção patrimonial não autoriza consultar imóveis ou veículos. Dados personalizados também podem aparecer no relatório sem um módulo correspondente.

`secoes` permite ordenar e renomear seções com `id` e `titulo`, além de incluir
`texto` opcional (1–20.000 caracteres). O texto é apresentado literalmente, escapado
e identificado como conteúdo fornecido pelo cliente. Não é uma instrução para
reescrever, enfatizar ou aprofundar os dados consultados.

Por exemplo, acrescente ao pedido combinado:

```json
{
  "secoes": [
    {
      "id": "cadastro_interno",
      "titulo": "Revisão interna do cliente",
      "texto": "Cadastro recebido. A decisão final depende da revisão da equipe responsável."
    }
  ]
}
```

Este trecho complementa o pedido, não é uma requisição completa. O ID corresponde
ao `section.id` existente ou ao ID do bloco personalizado, renderizado como
`provided-{id}`. Um ID desconhecido informa a indisponibilidade dos dados, sem
nova consulta. Seções de origem e risco permanecem no relatório.

**`descricao` é rejeitado. Esta versão não oferece composição semântica por texto
livre.** Não use IDs reservados de risco, o prefixo `provided-` em IDs de blocos ou
IDs de blocos que colidam com módulos selecionados. Não selecione o mesmo bloco
como `x` e `provided-x`. Essas colisões são rejeitadas antes da cobrança.
Sem `secoes`, a composição é padrão.

## Risco automático: seis classes fixas

O resultado estruturado inclui `result.risco`, sem exigir um campo de risco na entrada:

`credito`, `endividamento`, `patrimonio`, `judicial`, `societario` e `compliance`.

Cada classe informa `status`, `motivos`, `evidencias` e `cobertura`, com os módulos consultados, ausentes e limitações. A versão `evidence-only/1.0` retorna `dados_insuficientes` nas seis classes enquanto não houver política calibrada. Ela organiza evidências e insuficiências: **não determina risco baixo, médio ou alto**. `nao_avaliado` e `dados_insuficientes` não significam baixo risco. O campo `nivel` só pertence a uma classe com status `avaliado`.

As seis classes são fixas mesmo quando o pedido consulta apenas um módulo. A ausência de dados não é preenchida como zero, falso ou aprovação. Não envie `risco` no POST.

## Obter o PDF

1. Crie com `POST /dossies`, `Authorization: Bearer <chave>` e `Idempotency-Key`.
2. Guarde o `id` retornado no `202` e acompanhe `GET /dossies/{dossie_id}/status`, respeitando `poll_after_seconds`.
3. Consulte `GET /dossies/{dossie_id}` para ler `coverage`, `result` e `artifacts`.
4. Em `artifacts`, use `download_url` do item `type: "dossie_pdf"` quando `status` for `available`. Observe `expires_at` e `available_until`; consulte novamente se a URL expirar.

Não há nova rota de PDF para dados personalizados. `needs_review` pode entregar resultado parcial e exige revisão, não aprovação automática. O PDF preserva a distinção entre fontes consultadas e conteúdo fornecido.

## Avançado: acesso, validação e compatibilidade

### Habilitação da conta

Use uma versão que disponibilize o contrato e uma chave válida vinculada ao workspace. O acesso ao produto exige a flag atual `public_api_dossies` na conta/workspace. Módulos ou dados personalizados exigem também `public_api_dossies_custom`, desligada por padrão. Não há escopos, requisito de geração da chave nem permissões de produto fixadas na emissão. Habilitar a conta não exige emitir ou rotacionar a chave.

A habilitação é administrativa e pertence à conta da chave. Não envie flags no JSON. Sem liberação, a API retorna `403 dossie_custom_not_enabled` antes de aceitar, cobrar ou enfileirar. O retry revalida a permissão.

### Idempotência e limites

Repetir `Idempotency-Key` com o mesmo conteúdo retorna o aceite anterior. Alterar módulos ou dados com a mesma chave retorna `409`. Para um novo conteúdo, use outra chave.

`POST /dossies/{dossie_id}/retry` mantém a configuração original e usa uma nova chave de idempotência. Não altera os dados do relatório.

O corpo aceita até 256 KiB. Campos desconhecidos, listas vazias de módulos/dados, duplicatas e tipos inválidos são rejeitados. `kind` mantém a política de cobrança existente e não adiciona módulos omitidos. Consulte os limites por campo na referência do POST e [os erros da API](/plataforma/erros).

### Integrações legadas

Os formatos anteriores com `mode`, `modules` em objeto e `data` em objeto continuam aceitos para compatibilidade, mas estão depreciados para novas integrações. A matriz opcional `risk_matrix`, aceita inclusive sem `mode`, e o retorno `risk_classification` pertencem a esse contrato legado; não são necessários para `result.risco`. Não use uma matriz de entrada como requisito do novo fluxo.
